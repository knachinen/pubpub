## 개발 과정 

GPT-OSS 모델로 페이즈2까지 구현을 마치고,  
페이즈3는 건너뛰더니 페이즈4 구현중에 토큰을 다 썼다.  

클로드로 모델을 바꿨는데,  
GPT-OSS 와 토큰 사용량을 공유하는건지 토큰을 다 썼다고 했다.  

할 수 없이 Gemini 3 Pro (Low) 모델로 구현을 시작했다.  

작업목록에 페이즈3는 체크되어 있지 않았는데,  
똑같이 건너뛰고 페이즈4부터 구현을 했다.  

작업을 중단시키고, 페이즈3부터 하라고 요청했고,  
코드를 살핀 후 이미 구현이 되어 있단다.  

(아니, 그러면 작업목록에 체크를 했어야지!)

## 결과 

오류.  
앱이 시작도 안된다.  

### 오류 수정

알아서 고치라고 맡겼는데,  
서너번 됐다고 해서 해보면 여전히 같은 문제로 되지 않았다.  

![[p05-w01-5_redbox.png|300]]

콘솔에는 오류 메시지가 없어서,  
스크린샷을 Gemini 웹에 넣고 물어봤다.  

> [!BUG] 
> 제공해주신 스크린샷은 React Native 애플리케이션에서 가장 흔히 볼 수 있는 **Redbox (빨간 화면)** 오류이며, 메시지는 **`[runtime not ready]: TypeError: "is not a function"`**입니다.
> 
> 이 오류는 JavaScript 런타임이 코드를 실행하려 할 때, **특정 변수나 객체에 존재해야 할 함수(메서드)**가 존재하지 않아 호출할 수 없을 때 발생합니다. 이는 애플리케이션의 **초기화 과정(Startup)**에서 발생했을 가능성이 높습니다.
> 
> 콘솔 오류 메시지가 없다고 하셨는데, 이 Redbox 화면 자체가 디바이스 앱의 **최초 실행 시점**에 발생한 치명적인 런타임 오류를 나타냅니다.


스스로는 오류를 못 고칠 것 같아서, 하나씩 해보기로 했다.  


> [!QUESTION] 
> 일단 App.tsx 대부분 주석처리를 하고, 일단 앱을 정상적으로 실행되게 먼저 만들자. 코드를 삭제하지 말고 주석처리하자.

젬씨 (Gemini CLI) 쓸때도 그랬는데,  
언어모델 특징이 코드를 주석처리하지 않고 삭제한다는거다.  

그래놓고 토큰에 걸리거나 뭔가 오류가 나거나하면 코드를 몽땅 잃어버린다.  
깃을 필수로 쓰거나, 주석처리를 강요해야 한다.  

주석을 하나씩 풀면서 폰트로딩이 되고,  
초기화면이 보이고,  
결국에는 코드에 마크다운 문법이 섞여있는 것을 발견해서 오류가 고쳐졌다.
