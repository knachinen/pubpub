## 계획

클로드가 작성해준 계획에서,  
Expo Go 옵션과 개발 빌드 옵션 중에서 개발 빌드 옵션을 선택했다.  

javascript 로 되어 있어서, typescript 로 변경한 뒤 진행했다.  

> [!NOTE] 프로젝트 목표 설명
> 
> **이름:** 모바일 웹 브라우저 (Mobile Web Browser)
> 
> **기술 스택:** React Native, Expo, TypeScript
> 
> **특징:** 탭 관리, 북마크, 방문 기록 추적 기능을 갖춘 전체 $\text{WebView}$ 기반의 프리미엄 $\text{UI}$ 구현.

> [!WARNING] 구현 접근 방식 및 제약 사항
> 
> - **핵심 기술:** $\text{TypeScript}$ 및 `react-native-webview`
>     
> - **주의 사항:** `react-native-webview`를 사용하므로, $\text{Expo Go}$ 환경에서는 호환되지 않으며 **개발 빌드(Development Build)가 필요**합니다.
>     

> [!CODE] 핵심 종속성 (Core Dependencies)
> 
> **[수정] package.json** 파일에 다음 필수 종속성을 추가합니다.
> 
> - `react-native-webview`: 웹 페이지 렌더링 엔진
>     
> - `@react-navigation/native`: 메인 네비게이션 프레임워크
>     
> - `@react-navigation/bottom-tabs`: 하단 탭 네비게이션 구현
>     
> - `@expo/vector-icons`: $\text{UI}$ 아이콘 라이브러리
>     
> - `react-native-safe-area-context`: 노치 디자인 기기 안전 영역 처리
>     
> - `react-native-screens`: 네이티브 화면 최적화
>     
> - `@react-native-async-storage/async-storage`: 북마크/방문 기록을 위한 영구 로컬 저장소
>     

> [!FOLDER] 프로젝트 구조
> 
> **[신규] src/ 디렉토리 구조**를 생성하여 체계적으로 관리합니다.
> 
> - `components/`: 재사용 가능한 $\text{UI}$ 컴포넌트 저장 (예: 주소 표시줄, 탭 항목)
>     
> - `screens/`: 메인 화면 컴포넌트 저장 (예: 브라우저 화면, 북마크 화면)
>     
> - `utils/`: 유틸리티 함수 및 헬퍼 저장 (예: 시간 형식 지정, $\text{URL}$ 유효성 검사)
>     
> - `constants/`: 테마, 색상 및 상수 정의 파일 저장
>     

> [!TIP] 테마 및 디자인 시스템
> 
> **[신규] src/constants/theme.js** 파일에 세련된 디자인 시스템을 정의합니다.
> 
> - **색상 팔레트:** 프리미엄 그라디언트 색상 (보라/파랑 테마)
>     
> - **타이포그래피:** 사용자 정의 글꼴 크기 및 두께 정의
>     
> - **간격:** 일관된 간격 스케일 ($\text{Spacing}$) 적용
>     
> - **그림자:** 입체적인 카드 효과 ($\text{Shadows}$)를 위한 스타일 정의
>     
> - **다크 모드:** 부드러운 전환 효과를 포함한 전체 다크 모드 지원
>

## 결과 

Expo Go 가 확실히 좀 더 편하긴 하다.  
구현이 끝나고 개발 빌드 소요시간이 Expo Go 보다 더 걸린다.  

결과는 꽤 괜찮았다.  
항상 안드로이드 상단바와 하단바를 고려하지 않는 점만 빼고는 괜찮았다.  

앞-뒤 버튼, 북마크 사이트 클릭시 이동, 히스토리 사이트 클릭시 이동 등  
모든 기능이 구현된건 아니지만, 나름 최소기능은 구현이 되었다.  

디자인도 투박하지 않고 괜찮다.
